# AGENTS.md — elin-decompile-toolkit repo conventions

Most agents read this file automatically as project context. The operational workflows (first-time setup, version diffing, knowledge-base building, the full pitfall log) live in [SKILL.md](SKILL.md) and are not repeated here; when the two disagree, `SKILL.md` wins.

## What this repo is

An Agent Skill that teaches an AI agent to extract official data from a locally installed copy of Elin and decompile its source. The repo root is the skill itself; users install it with `npx skills add piexian/elin-decompile-toolkit`, or by copying the whole directory into their agent's skills directory.

```
SKILL.md     Agent entry point (frontmatter, CLI workflows, iron rules, version-diff lessons and pitfalls)
AGENTS.md    this file
README.md    human-facing install guide (Chinese)
README_en.md human-facing install guide (English)
scripts/   unified CLI and the only implementation
data/version_changes.json  version-change source table, rendered by `scripts corpus build`
```

`data/version_changes.json` is a **checked-in source table**, not a generated artifact: edit it to record what a game version changed, and `scripts corpus build` turns it into `work/<channel>/<version>/kb/corpus/versions/`. The same schema (`sections` / `points`) applies to any file you add under `data/knowledge/`.

## Data generated by the CLI (not committed, see .gitignore)

| Path | Contents | Produced by |
|---|---|---|
| `work/<channel>/<version>/data/lang/` | official Chinese language pack, 83 tables | `python -m scripts data extract --all` |
| `work/<channel>/<version>/data/*.json*` | strict item, material, element, character, zone, quest and religion data | `python -m scripts data extract --all` |
| `work/<channel>/<version>/src/` | UTF-8 decompiled source or `ilspycmd -p` project | `python -m scripts decompile` |
| `work/<channel>/<version>/kb/source/classes/` | per-class source files for optional code chunks | `python -m scripts source split` |
| `work/<channel>/<version>/kb/` | RAG corpus and AstrBot upload chunks | `corpus build` and `chunks` |
| `work/<channel>/<version>/reports/` | generated wiki pages and cropped sprites | `pages` and `sprites` |
| `work/<channel>/<version>/ylvapedia/cache/` | optional source-stamped Ylvapedia page and revision cache | `python -m scripts ylvapedia fetch` / `revisions` |

Checked in (not generated): `data/version_changes.json` — the version-change source table rendered into the corpus by `scripts corpus build`. Add curated knowledge entries under `data/knowledge/*.json` with the same schema.

## Key locations

| Resource | Location |
|---|---|
| Main game DLL | `<game dir>/Elin_Data/Managed/Elin.dll` |
| Binary game data | `<game dir>/Elin_Data/sharedassets0.assets` |
| Character sprite atlas | `<game dir>/Package/_Elona/Texture/objs_C.png` — 128px cells, 32 per row, linear tile index from `charas_full.jsonl` `_tiles`; crop how-to in SKILL.md "Known pitfalls" |
| Character portraits (dialog art) | `<game dir>/Package/_Elona/Portrait/UN_<chara id>.png`; a character with no file there has no portrait |
| Book/reading-text files | `<game dir>/Package/<package>/Lang/<lang>/Text/Book/*.txt` (first line = `title,author,...`) |
| Official Simplified Chinese language pack | `<game dir>/Package/_Lang_Chinese/Lang/CN/` |
| Decompiled-code docs site (may lag the local version) | https://code.elin-modding.net/ |
| Official Elin MCP endpoint | https://mcp.elin-modding.net/ — remote `elin` knowledge server; setup instructions at `/llms.txt` |
| Elin MCP source and skill | https://github.com/Elin-Modding-Resources/Elin.MCP |
| Public decompile dump | https://github.com/Elin-Modding-Resources/Elin-Decompiled — static reference, not an MCP server |
| Chinese-language Elin wiki (target of the drafts) | https://elin.huijiwiki.com/ |
| Wiki image-upload rules (categories, naming) | https://elin.huijiwiki.com/wiki/MediaWiki:Uploadfiles-info |
| Ylvapedia MediaWiki API (optional supplement only) | https://ylvapedia.wiki/api.php ; use `parse/wikitext` or `query/revisions`, cache revision metadata and never replace official names/data |

The game directory is located automatically by `scripts` (`--game` first, then `ELIN_GAME_DIR`, Steam roots, `libraryfolders.vdf` and `appmanifest_2135150.acf`); run `python -m scripts check --game <game-dir>` to verify it.

## Optional Elin MCP integration

The remote `elin` MCP at `https://mcp.elin-modding.net/` is the preferred indexed source for modding lookups. The local `elin-runtime` MCP can execute C#, inspect logs, take screenshots, and hot-load patches in the installed game. The public `Elin-Decompiled` repository is only a static source dump and is not an MCP server.

Agents must inspect the connected tool list before setup, must not add duplicate MCP entries, and must not install anything by default. If a required server is missing, ask once whether the user wants setup; after approval follow `https://mcp.elin-modding.net/llms.txt`, verify release digests, restart the client, and run the documented checks. Runtime MCP executes code sent by a local client and should be disabled for normal play. Installation failures must include the command, verification result, and the matching official URL.

## Unified CLI and migration contract

The only supported implementation is `python -m scripts`. Keep each release in an isolated workspace:

```text
work/<channel>/<version>/{data,src,kb,reports,version.json}
```

Before using or publishing a workspace, the Agent checks `version.json`, channel, game DLL/assets hashes, strict row counts and ID sets, and that every output was produced from the same workspace. If legacy root-level `data/`, `src/` or `kb/` files are found, treat them as migration input only; do not mix them into a Stable or Nightly workspace. If a migration check fails, stop the pipeline, report the exact command and evidence, and repair the new CLI implementation before continuing.

The dependency preflight is read-only by default. Check Python, .NET SDK, `ilspycmd`, Node.js and Pillow only when the requested command needs them. Ask once before installing; after approval run the verified commands non-interactively. On Windows, use `winget` for missing Python/.NET/Node packages, `dotnet tool install --global ilspycmd` for `ilspycmd`, and `python -m pip install Pillow` for sprites. Installation failures must include the command, exit result and the matching official page; use the one-command domestic npm/PyPI fallback only when documented, never an unverified MCP or release mirror.

`data extract --all` includes the strict 13-row `SourceReligion` table. `pages gods` generates god/apostle drafts from that data and the official language pack. Ylvapedia commands are optional, cached supplements: record URL, revision, fetch time and hash, and leave official Chinese names and local mechanics data unchanged. Do not crawl the site or use its content for training.

## Local Python checks

CodeQL runs in GitHub; local agents must check Python scripts before relying on a script change:

```bash
python -m compileall -q scripts
ruff check scripts --select E9,F63,F7,F82
```

If `ruff` is unavailable and the task touches `scripts/`, install it before checking with `uv tool install ruff`. If `uv` is unavailable, use `python -m pip install ruff`; when the official PyPI request fails, retry that command with `--index-url https://pypi.tuna.tsinghua.edu.cn/simple`. Run Ruff in the same environment as the CLI. Use `ruff check scripts` for the required gate; do not reformat unrelated files.

## Iron rules

1. **Names must come from the official language pack in `data/lang/` — never self-translate.** External wikis (Ylvapedia etc.) only provide structural hints; keep the English/Japanese original marked "awaiting official translation" when no Chinese exists.
2. **Mechanics conclusions must be grounded in decompiled code or game data.** Community wikis are leads only. Mark numbers that cannot be measured from data as "estimated".
3. **Every wiki section carries a source annotation by default.** Each `==` / `===` section ends with an HTML comment naming where the content came from or what to search in the source — decompiled class and method, extracted table and row id, language-pack row and column, or the game file path. Write them unless the user asks for a page without annotations; the forms and the anchor list are in SKILL.md under "Writing wiki pages".
4. **Uploaded files follow the site's naming and category rules.** A `[[File:...]]` link stays red until the file exists, so images ship with the page. Sprites are cropped from the atlas (never screenshotted), names say what the file is, and every upload gets its category — `Sprite`, `立绘`, `能力`, `魔法`, `领域`, `物品`, `背景`, `PCC`, or `成就`. The full table and the naming rules are in SKILL.md under "Uploading images to the wiki".

## Modifying this skill

- After changing any script, repackage and re-verify in a clean directory; the verification steps and expected values live in the maintainer's workspace guide (not in this repo).
- The `SKILL.md` frontmatter only uses the two universal fields `name` + `description` — do not add agent-specific keys; keep the trigger words in `description` (Elin mechanics / official Chinese names / version changes / knowledge base).
- Known pitfalls (GBK re-encoding, the `*r` placeholder, AstrBot's chunking rules, `/tmp` paths, …) are recorded in `SKILL.md` under "Known pitfalls" — add new ones there when you fix them.
